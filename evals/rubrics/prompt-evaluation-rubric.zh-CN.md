# 提示评估量表

使用此量表来评估由仓库工作流生成的输出。

每个标准的评分范围为 **1 到 5**。

<a id="1-grounding"></a>
## 1. 事实依据

衡量声明是否由所提供的证据支持。

<a id="score"></a>
### 评分

- **5** - 所有重要声明均基于可用证据
- **4** - 大部分有依据，仅有轻微的未支持解释
- **3** - 部分声明缺乏支持或依据薄弱
- **2** - 多个重要声明缺乏证据
- **1** - 输出严重依赖虚构或未支持的信息

<a id="2-instruction-following"></a>
## 2. 指令遵循

衡量是否符合明确的任务约束。

示例：

- 读取必需文件；
- 保留现有内容；
- 避免无关修改；
- 使用请求的分类；
- 遵守隐私规则。

<a id="score-1"></a>
### 评分

- **5** - 完全遵循所有重要指令
- **4** - 一个轻微的指令未被遵循
- **3** - 部分遵循指令
- **2** - 未遵循多个重要约束
- **1** - 大部分忽略任务指令

<a id="3-output-structure"></a>
## 3. 输出结构

衡量输出是否符合请求的格式。

<a id="score-2"></a>
### 评分

- **5** - 完整且结构正确
- **4** - 结构正确，仅有轻微遗漏
- **3** - 可识别的结构但不一致
- **2** - 重要请求部分缺失
- **1** - 输出未遵循请求的结构

<a id="4-unsupported-claims"></a>
## 4. 未支持声明

衡量避免虚构的能力。

分数越高，表示未支持声明越少。

<a id="score-3"></a>
### 评分

- **5** - 无未支持声明
- **4** - 一个轻微的未支持陈述
- **3** - 多个薄弱假设
- **2** - 重要未支持声明
- **1** - 存在大量虚构或捏造

<a id="5-minimal-diff-behavior"></a>
## 5. 最小变更行为

衡量在编辑任务要求最小变更时，工作流是否保留有效现有内容。

<a id="score-4"></a>
### 评分

- **5** - 仅做出必要变更
- **4** - 存在少量不必要的编辑，无重要损失
- **3** - 存在明显的不必要的重写
- **2** - 尽管请求变更有限，仍进行了大规模重写
- **1** - 发生破坏性或不恰当的重写

对于非编辑类任务，将此标准标记为 **不适用**。

<a id="6-completeness"></a>
## 6. 完整性

衡量响应是否覆盖了任务的所有重要部分。

<a id="score-5"></a>
### 评分

- **5** - 所有重要要求均已满足
- **4** - 仅有一个轻微遗漏
- **3** - 有用但不完整
- **2** - 多个重要部分缺失
- **1** - 任务的主要部分缺失

<a id="scoring"></a>
## 评分标准

最高标准分数：

```text
30
```

如果`Minimal-diff behavior`不适用，则计算结果如下：

```text
25
```

<a id="interpretation"></a>
## 解释

对于30分的评估：

- **27–30** - 优秀
- **23–26** - 良好
- **18–22** - 可接受但需改进
- **12–17** - 较弱
- **6–11** - 评估失败

不要仅依赖总分。

若存在关键的 grounding 或 hallucination 失败，即使总分较高，也可能使结果无效。

<a id="regression-rule"></a>
## 回归规则

如果新提示版本出现以下情况，应进行审查：

- 总分显著下降；
- grounding 降低；
- 未经支持的断言增加；
- 一个此前被遵守的明确约束现在被忽略；
- 最小差异行为变得更差。

关键的回归情况应阻止新提示版本发布，直至审查完成。
