# 求职申请准备提示词

为一个明确选定的机会准备申请材料，但不提交申请。

<a id="read-before-starting"></a>
## 开始前请阅读

1. `AGENTS.md`
2. 完整的职位发布及其权威来源
3. 已验证的候选人档案、项目、技能和经验记录
4. 现有申请材料和简历变体，如提供
5. `prompts/application/adapt-resume.md` 当需要做出简历决策时

<a id="objective"></a>
## 目标

生成一个有据可依的准备包，帮助候选人手动审查并提交一份强有力的申请。

<a id="analysis"></a>
## 分析

1. 提取实际职责、所需资格、优先资格、地点、时间以及申请限制。
2. 将职位发布中的事实与解释和缺失信息分开。
3. 将每个重要要求与候选人的证据进行匹配。
4. 将候选人的证据分类为：支持、部分支持、未记录、显著差距或可能阻碍的前提条件。
5. 仅选择最相关且最强的项目和经历。
6. 记录重要差距，而不是用更宽泛的表述来掩盖它们。
7. 如需要，应用 `REUSE`、`ADAPT` 或 `CREATE` 决策（来自 `adapt-resume.md`）。

<a id="grounding-rules"></a>
## 依据规则

- 不得虚构技能、经验、指标、成果、职责、语言水平、可用性或动机。
- 不得从职位发布中推断候选人的证据。
- 必须保持源证据的含义和限制。
- 将内部文件路径和私人笔记排除在面向候选人的文档之外。
- 仅当有可靠来源支持时，才将公司信息视为当前有效。
- 区分事实与建议和提议的表述。

<a id="optional-cover-letter"></a>
## 可选的自荐信

仅在被请求时创建自荐信。将候选人的每一个主张都基于所提供的证据进行支撑。将最强的证据与实际职位关联，诚实地陈述重要的学习领域，避免泛泛而谈的赞美或技术列表。当文档模板提供身份和联系方式字段时，将这些字段与生成的正文内容分开。

<a id="human-review"></a>
## 人工审核

候选人必须在提交前审查所有主张、表述、日期、联系方式和附件。不得提交表单、发送消息或进行批量申请。

<a id="output"></a>
## 输出

提供：

1. 已验证的机会摘要及其来源；
2. 要求到证据的分析；
3. 应重点强调的最强证据；
4. 差距和未支持的要求；
5. 简历决策及理由（如适用）；
6. 用户请求的建议申请材料；
7. 需要人工审核的事实或表述；
8. 手动下一步操作。

仅修改明确请求的应用文件。保留现有的源档案、项目记录、简历和模板。
