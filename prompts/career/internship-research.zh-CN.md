<a id="internship-research-prompt"></a>
# 实习研究提示

针对候选人的背景进行当前最新的实习机会搜索。

<a id="read-before-starting"></a>
## 开始前阅读

1. `AGENTS.md`
2. `local/career-profile.md`
3. `templates/internship-research-report.md`
4. 仅在需要进行重复检测或变更追踪时，查阅`local/research/`之前的文件。

<a id="objective"></a>
## 目标

找到真正符合候选人背景和限制条件的当前可访问的实习机会。

对于选定的职位，需确定：

- 每个职位的相关性原因；
- 主要请求的技能和技术；
- 哪些要求已由候选人的证据支持；
- 哪些要求仅弱有体现；
- 哪些要求尚未满足；
- 哪些现有项目提供了最强的证据支持；
- 哪些技能缺口在多个职位中反复出现；
- 哪些机会应被优先考虑；
- 候选人下一步应加强的内容。

<a id="research-rules"></a>
## 研究规则

- 在互联网上搜索当前的职位信息。
- 尊重候选人背景中规定的地理、职位类型、学历水平、时长和时间限制。
- 优先选择原雇主的职业页面。
- 不要将无法访问或明显已过期的职位视为当前有效。
- 评估实际职责和要求，而非仅看职位名称。
- 搜索与候选人背景定义的兼容职位类别和相邻技能领域，而非仅依赖一个职位名称或关键词。
- 将应用领域与技术适配性分开考虑。
- 在不同来源中去重相同报价，如有官方需求ID或申请链接，则使用这些信息。
- 区分可访问的职位列表与已被确认仍开放的职位。
- 仅在已验证的情况下记录发布日期。对于由相对表述推断出的日期，应标注为推断日期。
- 在可用的情况下保留官方需求ID，并优先使用官方雇主或ATS链接而非镜像链接。
- 不得推断未在所提供文件中支持的候选人的技能。
- 不要简单为了增加结果数量而包含弱相关职位。
- 保留用于验证所选职位的源URL或参考信息。
- 将事实与分析分开。
- 明确说明不确定性。

<a id="discovery-and-selection-boundary"></a>
## 发现与选择边界

将机会发现和申请准备视为两个独立阶段。该工作流可以对机会排序并生成报告。只有在用户明确选择职位后，才可以创建申请文件夹、修改简历或准备申请材料。

为每个入围职位分配一个在报告内唯一的编号（`O01`、`O02` 等），并在职位详情中重复该编号，方便用户按编号选择。

<a id="fit-evaluation"></a>
## 适配性评估

使用定性等级：

- **强**
- **良好**
- **部分**
- **弱**

除非明确定义了评分方法，否则避免使用人为的数值精度。

<a id="output"></a>
## 输出

使用：

```text
templates/internship-research-report.md
```

将个人报告保存至：

```text
local/research/YYYY-MM-DD-internships.md
```

如果该文件名已存在，使用下一个可用后缀（`-2`、`-3` 等）。除非用户明确要求修正旧报告，否则不得覆盖已有报告。

除非明确请求，否则不得修改候选人的资料或公开模板。
