# 通用仓库提示

从私有或本地源中提取一个可复用的公共仓库，同时保持其运行行为和私有边界。

<a id="define-before-acting"></a>
## 行动前定义

- 预期的公共用途和受众；
- 为实现该用途所需的功能组件；
- 必须保持不变且不公开发布的私有源内容；
- 完成时所需的独立验证。

在修改任一仓库之前，对源仓库和目标仓库进行审计。

<a id="method"></a>
## 方法

1. 检查源仓库中的当前实现、测试、文档、配置以及近期历史记录。
2. 检查目标仓库，并保持其身份、结构以及与之无关的本地变更。
3. 识别可复用的组件及其最小依赖项。
4. 提取稳定的模式，而不是复制特定任务的提示、私有记录、生成输出或本地历史。
5. 仅在必要时，将机器特定路径和私有常量替换为文档化的输入或配置。
6. 以最小的连贯目标差异来保持行为一致性。
7. 更新目标文档以匹配提取的实现。
8. 保持源仓库元数据和`.git/`历史记录不包含在复制内容中。保持现有目标历史记录，或仅在明确请求时创建新的独立历史记录。
9. 独立于私有源对目标进行验证。

<a id="privacy-and-safety-checks"></a>
## 隐私与安全检查

扫描候选内容和最终差异，以查找：

- 名称和联系方式；
- 用户名、个人网址和绝对路径；
- 凭证、令牌、密钥和本地数据库；
- 私有项目、客户、雇主或应用程序数据；
- 私有指标、基准、日志和生成的制品；
- 依赖于某用户本地结构的指令。

使用虚构或匿名示例。不要复制密钥后再在后续提交中进行擦除；在编写公开文件前就排除它们。

<a id="validation"></a>
## 验证

在相关情况下运行：

- 针对性和完整的相关测试；
- 静态、类型和构建检查；
- 独立的冒烟测试；
- 文档路径和链接检查；
- 密钥和隐私扫描；
- `git diff --check`及最终差异审查。

<a id="output"></a>
## 输出

报告：

1. 源与目标状态已检查；
2. 已提取可复用的模式；
3. 已刻意排除源特定内容；
4. 目标中新增、修改或删除的文件；
5. 验证与隐私结果；
6. 剩余限制。

除非明确请求，否则不得提交或发布。除非任务单独要求，否则不得修改私有源。
