# 仓库文档审计提示

审计仓库文档的准确性、完整性和一致性。

<a id="compare"></a>
## 对比

将文档与以下内容进行对比：

- 源代码；
- 配置；
- 命令行接口；
- 测试；
- 目录结构；
- 当前项目状态。

检查当前分支和`HEAD`。当存在冲突时，优先使用已执行的代码和测试，而非过时的文档。注意相关未提交或远程状态的差异，而不是将它们合并为一个项目状态。

<a id="identify"></a>
## 识别

- 过时的README部分；
- 未记录的重要模块；
- 已不再生效的命令；
- 缺失的配置步骤；
- 重复的文档；
- 被列为已实现的路线图项目；
- 术语不一致；
- 未记录的限制条件；
- 缺失基准上下文；
- 相关文档之间缺乏连接。

<a id="prioritization"></a>
## 优先级

将发现分类为：

- **关键**
- **重要**
- **轻微**

<a id="rules"></a>
## 规则

- 除非明确请求，否则不得在审计期间重写文档。
- 优先保证正确性而非完整性。
- 无需为琐碎的内部细节提供文档。
- 重点关注影响用户、贡献者、可复现性或项目理解的信息。
- 在检查前需明确审计范围和成功标准。

<a id="output"></a>
## 输出

生成一个包含以下内容的表格：

- 问题；
- 受影响文件；
- 证据；
- 建议变更；
- 优先级。
