# Mettre à jour le prompt de documentation du projet

Vérifier l'implémentation et la documentation technique existante.

Mettre à jour la documentation afin qu'elle reflète l'état actuel du référentiel.

<a id="rules"></a>
## Règles

- Faire les modifications les plus petites et utiles.
- Conserver le contenu valide existant.
- Privilégier les ajouts par rapport aux réécritures inutiles.
- Documenter uniquement des approches abandonnées lorsque celles-ci fournissent un contexte utile.
- Ne jamais documenter une fonctionnalité qui n'existe pas dans le référentiel.
- Faire une distinction claire entre le comportement actuel et les travaux futurs.
- Maintenir une terminologie cohérente avec le codebase.
- Conserver les résultats historiques utiles lorsqu'ils restent pertinents.
- Supprimer des instructions obsolètes qui pourraient tromper un contributeur.

<a id="check"></a>
## Vérifier

Revue :

- architecture ;
- flux de travail ;
- configuration ;
- utilisation de la ligne de commande ;
- tests ;
- problèmes connus ;
- résultats d'évaluation ;
- objectif actuel ;
- objectif suivant.

<a id="output"></a>
## Sortie

Modifier uniquement les fichiers de documentation pertinents.

Fournir un résumé concis des modifications.
