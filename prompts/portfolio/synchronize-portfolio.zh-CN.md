# 投资组合同步提示

将公开投资组合与当前验证的知识库同步。

<a id="read-before-starting"></a>
## 开始前阅读

1. `AGENTS.md`
2. 相关项目档案
3. 相关技能记录
4. 职业或目标职位信息
5. 当前投资组合仓库

在编辑之前，检查两个工作树，识别必须保留的无关本地变更。

<a id="source-of-truth"></a>
## 事实来源

将验证知识库视为事实来源，用于：

- 项目状态；
- 项目描述；
- 技术栈；
- 已展示的技能；
- 里程碑；
- 可衡量成果。

将投资组合视为公开展示层。

<a id="objective"></a>
## 目标

更新投资组合，使其反映当前候选人的档案，同时不暴露不必要的私有或内部信息。

审查：

- 重点项目；
- 项目状态；
- 项目描述；
- 技术栈；
- 技能；
- 项目与技能之间的关系；
- 链接；
- 当前职位定位；
- 过时的声明。

<a id="rules"></a>
## 规则

- 不得虚构投资组合中的声明。
- 不得添加未在知识库中支持的技能。
- 不得暴露私有笔记、内部评估或申请数据。
- 直接将当前投资组合与当前事实来源进行对比；不得假设之前的同步仍然有效。
- 除非有明确的结构变更理由，否则保持现有投资组合结构。
- 优先采用最小差异。
- 不得发布每一个内部里程碑。
- 仅呈现对外部读者（如招聘人员或技术评审员）有用的信息。
- 保持项目表述简洁且基于证据。
- 确保项目状态与当前事实来源一致。
- 除非另有明确请求，否则保持重点项目的限制。
- 不得用较新但较弱的项目替代更强的项目证据。
- 避免在多个描述中重复展示同一能力，除非确实增加价值。
- 保留投资组合仓库中的无关本地变更。
- 在修改后验证投资组合构建或等效的相关检查。

<a id="synchronization-checks"></a>
## 同步检查

<a id="projects"></a>
### 项目

针对每个投资组合项目，验证：

- 名称；
- 状态；
- 描述；
- 技术栈；
- 链接；
- 关键证据；
- 是否仍应作为重点项目。

<a id="skills"></a>
### 技能

验证每个展示技能均得到以下内容的支持：

- 项目；
- 课程学习；
- 职业经历；
- 其他书面证据。

<a id="positioning"></a>
### 定位

检查投资组合是否仍反映了候选人的当前目标职位及其最强的技术领域。

<a id="output"></a>
## 输出

提供：

1. 应更改的文件；
2. 过时的精确信息；
3. 建议的最小更新；
4. 故意不公开的信息；
5. 应手动审查的投资组合不一致之处。

如果请求文件修改，仅应用必要的更改。

在投资组合同步过程中，不得修改私有知识库。
