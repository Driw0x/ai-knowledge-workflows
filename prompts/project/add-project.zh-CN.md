# 添加项目提示

检查目标仓库并仅使用可验证信息创建结构化的项目条目。

<a id="read-before-starting"></a>
## 开始前请阅读

1. `AGENTS.md`
2. `templates/project-profile.md`
3. 相关仓库文件
4. 若可用，现有知识库规范

在撰写前，明确成功标准、目标项目目录以及必须保持不变的文件。

<a id="objective"></a>
## 目标

创建一份简洁但实用的项目记录，涵盖：

- 项目目标；
- 解决的问题；
- 当前状态；
- 实际使用的技术；
- 重要的架构或方法；
- 展示的技能；
- 已验证的里程碑；
- 可量化的成果；
- 局限性；
- 下一个相关的里程碑。

<a id="rules"></a>
## 规则

- 在依赖README中的声明之前，必须检查实现细节。
- 检查当前分支和`HEAD`；当相关时，需区分当前文件与远程状态或历史实验之间的差异。
- 使用测试和基准成果作为证据，并说明在分析过程中是否执行了重要的检查，或者仅进行了记录。
- 不要推断未在仓库中实际使用的技术。
- 不要在没有具体证据的情况下声称具备某种技能。
- 区分已实现的功能与计划中的工作。
- 区分当前活跃的方案与已放弃的实验。
- 在术语清晰且准确时，保留仓库中的术语。
- 避免逐字复制README中的大段内容。
- 优先选择持久的信息，而非临时的调试细节。
- 当未提交的变更可能影响观察到的状态时，报告仓库的整洁程度。

<a id="output"></a>
## 输出

使用`templates/project-profile.md`。

如果知识库有项目目录约定，将新条目放置在该目录下。

不要修改无关的项目文件。
