# Évaluer le prompt du projet

Évaluer le projet comme preuve des rôles techniques ciblés du candidat.

<a id="read-before-starting"></a>
## Lire avant de commencer

1. `AGENTS.md`
2. Le dépôt de projet
3. La documentation existante du projet
4. Les définitions du profil professionnel ou des rôles cibles, si disponibles

Examiner l'implémentation actuelle et les tests avant de faire confiance aux affirmations du projet. Utilisez la branche actuelle et `HEAD` comme état évalué, et indiquez les différences pertinentes liées à des modifications non commitées ou à l'état distant.

<a id="evaluation-dimensions"></a>
## Dimensions de l'évaluation

Évaluer :

- la profondeur technique ;
- la maturité de l'implémentation ;
- la pertinence pratique ;
- l'originalité ;
- la reproductibilité ;
- la qualité des tests ;
- la qualité de la documentation ;
- les résultats mesurables ;
- la valeur dans le portfolio ;
- la valeur en entretien ;
- l'alignement avec les rôles cibles.

<a id="skill-evidence"></a>
## Preuves de compétences

Pour chaque compétence importante, classer la preuve comme :

- **Fort**
- **Modéré**
- **Faible**
- **Non soutenu**

Expliquez les preuves sous-tendant chaque classification.

Distinguez les travaux mis en œuvre, testés, validés, expérimentaux, planifiés, abandonnés ou remplacés. Un plan d'avenir ou une expérience historique n'est pas une preuve actuelle.

<a id="decision"></a>
## Décision

Recommandez l'un des suivants :

- **Continuer**
- **Renforcer avant de le montrer**
- **Montrer maintenant**
- **Pausé**
- **Archivé**

<a id="output"></a>
## Sortie

Inclure :

1. un résumé du projet ;
2. les compétences les plus démontrées ;
3. les faiblesses ou l'absence de preuves ;
4. les familles de rôles les plus adaptées ;
5. la prochaine étape de valeur maximale ;
6. la recommandation finale.

Ne récompensez pas la complexité pour elle-même.

Préférez des améliorations qui augmentent les preuves réelles, l'utilisabilité, la reproductibilité ou la pertinence.
