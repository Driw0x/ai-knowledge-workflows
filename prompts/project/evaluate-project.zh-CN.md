# 评估项目提示

将该项目作为候选人目标技术岗位的证据进行评估。

<a id="read-before-starting"></a>
## 开始前请先阅读

1. `AGENTS.md`
2. 项目仓库
3. 现有项目文档
4. 如有相关职业档案或目标岗位定义，请一并参考

在依赖项目声明前，请检查当前实现和测试情况。以当前分支和`HEAD`作为评估状态，并披露相关未提交或远程状态的差异。

<a id="evaluation-dimensions"></a>
## 评估维度

评估：

- 技术深度；
- 实现成熟度；
- 实际相关性；
- 原创性；
- 可复现性；
- 测试质量；
- 文档质量；
- 可衡量成果；
- 作品集价值；
- 面试价值；
- 与目标岗位的匹配度。

<a id="skill-evidence"></a>
## 技能证据

对于每一个重要技能，将其证据分类为：

- **强**
- **中等**
- **弱**
- **不支持**

解释每一类别的证据依据。

区分已实现、已测试、已验证、实验性、计划中、已放弃和已被替换的工作。路线图或历史实验不构成当前证据。

<a id="decision"></a>
## 决策

推荐以下之一：

- **继续**
- **加强后再展示**
- **现在展示**
- **暂停**
- **归档**

<a id="output"></a>
## 输出

包含：

1. 项目概述；
2. 最突出展示的技能；
3. 弱点或缺失的证据；
4. 最匹配的角色类别；
5. 最高价值的下一步里程碑；
6. 最终建议。

不要因复杂性本身而奖励复杂性。

优先选择能够提升真实证据、可用性、可复现性或相关性的改进。
