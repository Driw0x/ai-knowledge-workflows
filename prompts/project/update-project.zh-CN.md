# 更新项目提示

检查当前项目仓库，并将其与现有知识库条目进行对比。

<a id="objective"></a>
## 目标

仅更新实质性发生变化的信息。

在编辑前，明确预期的更新内容，确定哪些有效内容必须保留，并列出验证结果所需的检查项。

审查：

- 项目状态；
- 里程碑；
- 已实现的功能；
- 架构或方法；
- 技术栈；
- 展示的技能；
- 基准或评估结果；
- 局限性；
- 已放弃的方案；
- 下一步计划。

<a id="rules"></a>
## 规则

- 保留现有有效信息。
- 优先选择最小差异。
- 优先添加内容，而不是不必要的重写。
- 移除或修正已不再真实的声明。
- 不要将路线图项目描述为已实现。
- 不要推断技能或技术。
- 以仓库证据为主要来源。
- 检查当前分支和`HEAD`。在相关情况下，区分当前实现与远程状态、正常Git历史记录以及废弃的本地或检查点工作。
- 将测试和基准仅在其实际范围内视为证据。说明结果是在更新过程中重现的，还是仅被记录的。
- 区分已实现、已测试、已验证、实验性、计划中、已废弃和已被替换的工作。
- 保留一个重要结果是被重现、仅记录、历史性的还是已被取代的状态。
- 仅在提供有用的项目背景时保留历史信息。
- 当相关时，明确标注暂停、放弃、实验性或已完成的工作。
- 当本地更改可能影响观察到的状态时，报告仓库的整洁性。

<a id="output"></a>
## 输出

原地更新现有项目记录。

最后，提供一个简要总结：

- 发生了什么变化；
- 哪些内容是故意保留的；
- 仍存在的任何不确定性。
