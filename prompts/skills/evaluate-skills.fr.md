# Évaluer les compétences démontrées : prompt

Examinez les preuves disponibles et déterminez les compétences réellement démontrées.

<a id="evidence-sources"></a>
## Sources de preuves

Utilisez uniquement des sources pertinentes telles que :

- des projets ;
- du code source ;
- des tests ;
- des benchmarks ;
- des travaux académiques ;
- de l'expérience professionnelle ;
- des documents techniques ;
- des résultats reproduisibles.

<a id="classification"></a>
## Classification

Pour chaque compétence, classez les preuves comme :

- **Fort** - preuves répétées ou substantielles
- **Modéré** - preu- uves claires, mais avec une profondeur ou une portée limitée
- **Faible** - preuves indirectes ou minimales
- **Non soutenu** - aucune preuve fiable

<a id="rules"></a>
## Règles

- Ne pas inférer une compétence à partir d'une mention d'une technologie effectuée une seule fois.
- Ne pas égaler une liste de dépendances d'un projet à une compétence démontrée.
- Distinger l'utilisation d'une maîtrise.
- Privilégier les preuves d'implémentation concrète par rapport à une description subjective.
- Identifier le projet le plus fort de soutien pour chaque compétence.

<a id="output"></a>
## Sortie

Pour chaque compétence évaluée, fournissez :

- nom de la compétence ;
- niveau de preuve ;
- preuves de soutien ;
- projet ou expérience de soutien le plus fort ;
- limitation ou incertitude.

Identifie également :

- nouvelles compétences démontrées ;
- compétences dont les preuves ont été renforcées ;
- compétences qui ne devraient pas encore être affirmées de manière prominente.
